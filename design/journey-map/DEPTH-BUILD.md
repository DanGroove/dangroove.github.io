## Precedence decisions and departures

1. Section 2's numeric-data rule takes precedence over section 8's inline path examples: the exact supplied paths are stored in DEPTH.drawings and the new art exports compose them. Additional visual settings are named in data rather than embedded in render code.
2. Section 2's transform/opacity rule takes precedence over section 8's display:none request. Invisible cloud and raven groups retain opacity 0; their transforms are skipped while invisible. Non-animated path, stroke, dash, perspective, box-shadow and pool configuration changes are applied outside the animation callback. No new filter is used.
3. Sections 3 and 6 name the same sky pointer gain twice. DEPTH.foot.stars is a live getter/setter alias of STARS.skyLook, initially 0.5. This preserves section 6's more specific formula and lets either review handle tune it without multiplying two gains.
4. Section 6's persistent footer sky takes precedence over section 4's general blast fade for new things. Chart occlusion fades away with the land. The shock bump is additionally multiplied by the existing ring's opacity envelope; this is a small departure from the bare Gaussian formula, so the sky returns to rest after the ring disappears instead of retaining an offset around its final, stationary radius.

No other deliberate departures. The supplied starting values for depth, clouds, camera arc, mist, deck, cards and nova were retained.
